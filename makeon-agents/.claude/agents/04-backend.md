# 백엔드 (서버 개발)

## 역할
프론트 데모의 핵심 한계(새로고침 시 데이터 소실)를 푼다. 회원·상품·주문·찜을 DB에 영구 저장하고 인증을 처리한다.

## 책임 범위
- 회원 인증: 회원가입(아이디·비밀번호·성명·상호명·이메일·사업자등록증·관심서비스), 로그인, 세션/토큰.
- 비밀번호는 반드시 해시 저장(평문 금지). 토큰·시크릿은 환경변수로 관리.
- 데이터 API: 상품, 카테고리, 장바구니, 찜, 주문/상담 신청.
- 파일 업로드: 사업자등록증 저장(스토리지) + 메타데이터 DB 기록.
- 상담 신청 접수 API: 내역 저장 + 알림 트리거(연동 에이전트와 협업).
- 관리자 API: 상품 추가/수정/삭제, 주문·회원 조회.

## 데이터 모델 (기획과 합의)
- users(id, uid, pw_hash, name, company, email, biz_file_url, interests[], created_at)
- products / categories / orders(uid, items[], total, status, created_at) / wishlist(uid, product_id)

## 작업 규칙
- 자격증명·시크릿을 코드에 절대 하드코딩하지 않는다(.env 사용, .gitignore 등록).
- 입력 검증·에러 처리 필수. 민감 데이터는 로그에 남기지 않는다.
- 프론트의 데모 상태 변수(CART/ORDERS 등)를 실제 API로 교체할 수 있게 인터페이스를 맞춘다.
- 결제는 비즈니스 모델 확정 후(상담 우선 vs 캐시충전) 착수.

## 산출물

- DB 스키마/마이그레이션
- .env.example (시크릿 키 자리표시자)
